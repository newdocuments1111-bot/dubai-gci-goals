- Keep GCI and completion-time calculations in the browser-safe `src/lib/gci.ts` module with unit tests; the page uses the same calculations for both input modes to avoid inconsistent targets.
- Real HubSpot leads and "Save to HubSpot" stay Elite Visions-only (owner email / HQ check server-side) because HubSpot is HQ's own connected account; the UI gate is cosmetic.
- Multi-agency access: every business row has agency_id (default my_agency_id(), child rows inherit from their lead by trigger); RLS helpers is_hq_admin/is_agency_member/is_agency_owner/can_access_lead enforce hq (read all), owner (whole agency) and agent (agency rows + assigned leads). Server functions call getAccess()/requireOwner()/requireHq() from browser-safe agency-access.ts and always filter list queries by the caller's agency so HQ never sees mixed agencies on normal pages.
- Private routes live under the client-only _authenticated layout, which loads the membership into route context (useMembership) and sends people without an agency to /onboarding; self sign-up creates an agency via create_my_agency, invites go through the admin invite API only after an owner/HQ check, and the plan login limit is enforced again by a database trigger.
- Storage paths are agency-scoped: documents/<agency>/<lead>/…, listing-media|listing-photos/<listings|photos>/<agency>/…, chat-media/<lead>/…; single-level legacy listing files belong to Demo Agency.
- Deal maths, goals, login limits, leaderboard and hours-saved live in browser-safe agency.ts with tests; ai_handled and closed_at are set by the deals trigger, usage_events rows come from a chat_messages trigger so the billing meter cannot be skipped.
- Missed-lead alerts are created by check_missed_leads() when the home or HQ screen loads (no polling job), since alerts are only shown in the app.
- Paperwork (Form F / Ejari) drafts and checklists come from browser-safe paperwork.ts using vault file names; drafts are always labelled as drafts and never filed anywhere.
- Market insights (price per sq ft by area/type/month) are computed in browser-safe market.ts from shared market_transactions; shared market data and UAE knowledge are read by every agency and edited only by HQ.
- Future reply defaults and validation live in a browser-safe module; app_settings and ai_reply_settings hold one row per agency (unique agency_id, owner-only writes), without activating messaging automation.
- Owner app modules: settings.ts, knowledge.ts, market.ts, leads-app.ts, documents.ts are browser-safe helpers with unit tests; their *.functions.ts counterparts use requireSupabaseAuth + agency access checks.
- Test Chat and WhatsApp share one reply brain in ai-reply.server.ts (model call via chat.server.ts generateJson); Test Chat queues replies in client quiet hours, WhatsApp answers immediately.
- Test Chat policy and consent transitions live in browser-safe chat-policy.ts with tests; persist invitation/offered/selected state in reserved learned fields so generated prose cannot bypass booking agreement. Shared viewing-slots.ts and viewings.server.ts calculate availability for both chat and Viewings; recheck slots before booking and confirm only after a successful insert.
- New media and public-demo AI calls use the generated @lovable.dev/ai-gateway contracts; existing text and HubSpot calls retain their transport and model to avoid unrelated behavior changes.
- Chat media is inspected before private storage; identity-document images never enter storage or model conversation history, and owner-only thread reads resolve short-lived media links.
- Public demo context comes exclusively from browser-safe fictional fixtures; its privileged server access is limited to an atomic daily visitor counter, never owner data.
- Phone installation uses manifest-only metadata and derived app icons. The only service worker is `public/alerts-sw.js` for phone notifications: it has no fetch handler and caches nothing, so pages can never be served stale.
- Revival drafts require opted-in inactive leads, are deduplicated, and approval atomically rechecks consent/STOP/timing before adding any message.
- Document Vault: the private "documents" bucket has no storage policies for app users; documents.functions.ts checks can_access_lead_documents (owner, assigned agent, HQ), then uses signed upload/10-minute view links and writes document_log server-side (read-only for users), so no access path skips the audit log.
- Private pages render inside OwnerLayout from _authenticated/route.tsx: a sidebar with five sections (Today, Leads, Deals, Listings, Insights) plus Settings and Tools, section tabs, Ctrl+K search and one "New lead" button. Grouping and role visibility live in browser-safe `src/lib/nav.ts` (tested); pages keep their own URLs, so add a new page to a section there instead of a new top-level nav item.
- Chat coaching uses the generated @lovable.dev/ai-gateway contract in coach.server.ts; the conversation is passed as untrusted data.
- WhatsApp uses Meta's Cloud API directly; the signed webhook stores each change in whatsapp_webhook_events before processing (claim RPC, backoff) so retries never double-reply. Every send goes through deliverChatMessage, which rechecks sendBlockReason (test-mode safety list, STOP, 24-hour window) from browser-safe whatsapp.ts. Template messages go only through whatsapp_outbox (server-written, claim RPC) and processOutbox, which re-runs outboxDecision from whatsapp-templates.ts before every send and records the chat message before calling Meta so an uncertain send is never repeated.
- Subdirectories have their own AGENTS.md (src/lib/AGENTS.md holds the listings rules); read it before changing files there.
- Client message content stays in its original language; reply-i18n holds deterministic client wording/script and translation_en is the separate English owner display so WhatsApp never sends translations.
- Weekly reports use owner/HQ-only agency-scoped real-row source snapshots and browser-safe weekly-report calculations; the existing hourly SQL function freezes Monday sources and drafts idempotent viewing follow-ups without scheduled model calls.
- Post-viewing follow-ups have unique viewing_id/kind identity and atomic approval, consent/STOP/no-reply/quiet-hours checks; outside WhatsApp's 24-hour window require an approved template rather than sending free-form drafts.
- Lead pipeline (the 15-step "Ads, funnel and CRM" plan): the rulebook `lead_stages` (name, who, next action, due offset, checklist, message template per step; off-plan track for steps 10–13) is applied by the `leads_apply_rules` trigger, which also enforces the lost-reason rule and logs moves to `lead_events`; leads only move FORWARD from the app's own events (`chat_messages` ai/agent → 2, budget/area/timing → 3/4, viewing booked/done → 6/7, follow-up sent → 8, deal under offer/closed → 10/14) via `lead_advance`, never off not_now/lost/won. `ad_campaigns` are agency-scoped; `lead_report` (view) gives the owner numbers per source. Browser-safe rules in `src/lib/pipeline.ts` (tested), server functions in `pipeline.functions.ts`, pages `/pipeline` and `/ads`, plus a live section on the Monday report. The UI never writes stage_name, who, next_action or next_action_at, and never sends a message. Why: one editable rulebook, numbers computed in the database, and the WhatsApp flow moves leads without code changes.
- Lead Inbox and routing: portals, Zapier, Meta forms and websites POST to `/api/public/leads/intake` with the agency key (`lead_intake`, owner-only, rotated by `rotate_intake_key`); `intake_lead` (service role only) dedupes open leads by phone digits. The `leads_aa_route` trigger assigns unassigned new leads by `routing_rules` (first match by area/language/source), else round-robin over agents `in_rotation`, else the pool; `return_untouched_leads` (cron every minute + Inbox load) returns routed API/portal leads (intake = 'api'; WhatsApp chats stay with their agent while the AI talks) with no human message or viewing after `pool_after_minutes`; agents see the pool only through `pool_leads()` (no phones) and take leads with `claim_pool_lead` (daily limit). Parsing and listing matching live in browser-safe, tested `src/lib/inbox.ts`; pages `/inbox` and `/settings/routing`.
- Agent alerts: `alerts` rows of kind assigned / reminder / pool are claimed once by `claim_alert_deliveries` (sets pushed_at) and delivered by `/api/public/alerts/dispatch` (kicked by an alerts trigger via pg_net with the managed cron key, plus a minute job): Web Push from `src/lib/webpush.ts` (WebCrypto VAPID + aes128gcm, tested; keys in server-only `push_keys`) to each `push_subscriptions` row, and the Meta-approved `agent_new_lead_alert` utility template to the agent's own mobile (never pool alerts; WhatsApp test mode still applies). Reminders fire at two thirds of `pool_after_minutes`; the header bell polls alerts every 30 s.
- Ask your CRM (Today page): a question picks one of eight ready-made reports and a period. Browser-safe `src/lib/ask.ts` (tested) parses plain words and computes every number from the agency's own rows read with the caller's access rules; only when parsing is unsure does `ask.functions.ts` ask the model to choose a report id (it sees the question, never data, and never writes). Ads and Agents reports are owner-only.
- Deal Room (`/deal/$dealId`): step lists per deal kind (ready sale, off-plan, rent), money (`dealMoney`), buyer cost estimates and RERA Form A/B/I drafts live in browser-safe, tested `src/lib/dealroom.ts`; steps are created on first open (`deal_steps`), payments in `deal_payments`, numbered invoices only through `issue_deal_invoice` with frozen amounts (`deal_invoices`, printable at `/invoice/$id`). Edit rights follow `can_edit_deal` (owner or the deal's agent). `total_commission_percent` with `co_broker_percent` sets `commission_percent` (our GCI basis) by trigger, so every GCI figure elsewhere stays our share. Fee figures are agency settings (Settings → Deals and fees) and are always shown as estimates.
- Lead tools: import (`/leads/import`, browser-safe tested `lead-import.ts`; rows inserted with intake = 'import', phone duplicates skipped, never alerted, pooled back or counted as missed), saved lists (`lists.ts` filters stored per user in `saved_lists`), call log (`lead_calls`; an answered or call-back call sets first_reply_at, logs to `lead_events` and keeps a routed lead with its agent), matching buyers on a listing (`matchBuyers`), and calendar files for viewings (`calendar.ts`, plain .ics download so no client data goes into a URL).
- Seller side and rentals: owners carry a listing pipeline stage and intent; `listings.owner_id` links stock to its owner; the Owners page (`getSellerBoard`) shows the pipeline, an owner update built from real counts by tested `sellers.ts` (copied by the agent, never sent), leases inside the 90-day renewal window and `rent_cheques` (daily `rental_reminders` alert 3 days before due). Team: `agency_members.team_leader_id` lets a leader read and update their agents' leads through `is_my_team_agent` in the leads policies and `can_access_lead`; monthly targets (GCI, viewings, calls) show on Team and Today via `getTargets`. Nurture: `draft_nurture_checkins` drafts a 'nurture' follow-up every `nurture_days` for opted-in not-now leads; it is sent only through the existing approval flow. App language: `i18n.ts` + `useLang` translate the shell to Arabic and set dir=rtl; page bodies are English until translated page by page, so use logical classes (ms-, ps-, start-) in new layout code.
- Campaigns, brochure, records and page language: a campaign (`/campaigns`, owner only, tested `campaigns.ts`) puts one Meta-approved template per consenting lead into `whatsapp_outbox` with purpose `campaign`, `campaign_id` and `campaign_step`; the owner pressing Send is the approval, later steps wait as `scheduled`, and the send job re-checks every rule and cancels a follow-up once the client has written back (`followUpStopped`). The brochure (`/brochure/$listingId`, tested `brochure.ts`) is a print page that never shows internal notes and warns when the permit number is missing. `audit_log` is written only by the `zz_audit` triggers (`audit_row`) and by server functions through the service role, is read-only for owners and HQ (Settings › Records), and every export (`exportRecords`, `logListExport`) must write its log row before any file is produced; CSV cells are guarded against spreadsheet formulas in tested `records.ts`. The app language is one shared store in `use-lang.ts`; page text is translated with `t("English text", { blanks })` from `i18n.ts`, and the i18n test fails when a translated page uses text without Arabic.
- Money and ID, social posts and page language: every deal has one `deal_compliance` row (the deal's agent or the owner, by `can_edit_deal`), read-only for other members; the `zz_audit` trigger writes every change to `audit_log`. Browser-safe tested `aml.ts` decides when a goAML Real Estate Activity Report is due (cash of AED 55,000 or more, or any virtual asset); the app never checks a name against any list and files nothing, and the Deal Room card says so. Posting a listing to Instagram, Facebook or LinkedIn is a caption copied by the agent from tested `social.ts`, refused without a Trakheesi permit number, never an automatic post. Arabic now covers the menu plus Inbox, Leads, Today, Board, Viewings, Follow-ups and Deals; `use-lang.ts` holds one shared language for the whole app, and the i18n test fails when a translated page uses `t("...")` text with no Arabic line.
- Advert Check, Campaign Cost, Safe Calling, Reply Speed and Seller Finder: `advert.ts` (`advertCheck`, tested) is the one rule set for brochure and social post (permit number, price, agency RERA number, permit not ended; `listings.permit_expires_on` warns 14 days before) and both are blocked, not just warned, when it fails. `campaigns.ts` prices a campaign before Start (`campaignCost`; rates are estimates of Meta's fee) and `metaLimitRetry` puts a message refused with Meta error 131049 back in the queue at most twice (`whatsapp_outbox.meta_limit_retries`), re-running every send check. `calling.ts` (`callCheck`) reminds agents of UAE calling hours (9am–6pm Dubai), one call a day (warn), two a week and `leads.do_not_call` (stop) in `LeadCalls`; it never blocks logging a call and does not check the national Do Not Call Registry. `/reply-speed` (`replyspeed.ts`) measures Property Finder's published SuperAgent rules on the CRM's own leads; `first_reply_at` is the first reply by AI or agent. `seller-finder.ts` lists likely sellers from the agency's own owners and closed deals with a drafted message that is copied, never sent.
